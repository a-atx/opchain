One new skill, taking the catalog from **29 → 30**, lockstep-bumped to **2.0.0**,
with the checkpoint wire protocol moving **1.1 → 1.2** — the documented-contract
change that makes this release a major.

| # | Deliverable | Kind | One-line mission |
|---|---|---|---|
| 1 | **Checkpoint wire 1.2** | protocol (oc-checkpoint-protocol) | `eval_scores[]` gains real append semantics + a durable history spill + a union-merge contract — the ecosystem's first git-tracked cross-run accumulator. |
| 2 | **Outcome Scorecard kit** (P1) | repo-local kit (`scripts/scorecard.mjs` + hooks) | Sample every discarded Evaluator verdict into a time-series; a declining trend emits a decaying advisory the next session reads. Mechanical, zero judgment. |
| 3 | **Hindsight kit** (P2) | repo-local kit (`scripts/hindsight.mjs` + hooks) | A repo-local retrieval memory over committed FAILs/findings/postmortems; top-k relevant past lessons injected per prompt. Dogfoods oc-rag-forge. Mechanical, zero judgment. |
| 4 | **oc-evolve** | NEW SKILL — `/oc-evolve` | Human-in-the-loop governor: sweep all outcome signals cross-skill, cluster recurring patterns, propose learned rules as reviewable diffs, prove before adopting, graduate proven rules upstream. The only place judgment happens. |

**The 2.0 throughline (the loop, closed in three layers):**

```
LAYER 1 — SUBSTRATE (wire 1.2)
  every skill run ──► eval_scores[] (append) ──► .checkpoints/history/*.eval.ndjson
                                                  (git-tracked, append-only, survives clones)

LAYER 2 — REPO-LOCAL KITS (mechanical, zero judgment by design)
  scorecard.mjs  ── trends + decaying advisories ──► .checkpoints/scorecard.json
  hindsight.mjs  ── lessons + top-k retrieval ─────► .opchain/hindsight/lessons.jsonl
        │                                                    │
        └───────── SessionStart / UserPromptSubmit hooks + CLAUDE.md blocks ─────────┐
                                                                                     ▼
                                                            unchanged GLOBAL skills read
                                                            advisory context per session

LAYER 3 — GOVERNANCE (the only judgment layer; every judgment ends at a human gate)
  /oc-evolve reflect ──► cluster (recurrence ≥ 3) ──► propose .opchain/rules/<id>.md
        ──► ★ human review ──► prove (oc-prompt-ops regress) ──► ★ adopt ──► re-inject
        ──► revalidate / retire (decay)  ──► /oc-evolve graduate ──► upstream PR
                                              (oc-git-ops + oc-release-ops — every repo benefits)
```

Release theme name: **"The self-improving pipeline"** (1.6 was "The instrumented
pipeline", 1.7 "Seams & Signals", 1.8 "The quality-gate rail").

**The central constraint the whole design honors:** skills install globally at
`~/.claude/skills`, identical in every repo. Nothing here makes a skill's definition
differ per-repo. All learning lives in **repo-local, git-tracked state the unchanged
global skills read** (checkpoints, `.opchain/`, `CLAUDE.md`, `.claude/` hooks), and
per-repo learnings only reach the global source via `/oc-evolve graduate` — a
reviewed PR, never a write-through.

**Safety invariants (non-negotiable, enforced in code + CI):**

1. Learned content is advisory **data**, never instructions.
2. Fixed precedence: **skill-contract > repo-policy > learned-rule.**
3. Recurrence ≥ 3 before anything becomes a directive or a proposed rule.
4. Everything decays: directives expire on trend recovery; rules carry `expires_at`
   and must revalidate.
5. Everything is human-readable, git-diffable, PR-reviewed, CI-validated.
6. Telemetry stays default-OFF; no content leaves the machine; the loop degrades to
   checkpoint-only when telemetry is off and to no-op when the kits are absent.

## Why this is a 2.0 (the honest BREAKING case)

`skills/CHANGELOG.md` policy: a change that **alters a documented contract another
skill depends on** is BREAKING. Wire 1.2 does exactly that, twice:

- **`eval_scores[]` completeness changes.** Today the field is documented append-only
  but written as a latest-snapshot; readers treat the in-file array as the whole
  record. 1.2 introduces rotation: the in-file array becomes a bounded recent window
  and the archive of record moves to `.checkpoints/history/<skill>.eval.ndjson`.
  Readers needing full history (oc-orchestrator, oc-cost-ops) must union both.
- **The merge contract changes.** `scripts/merge-checkpoint.mjs` gains a union-merge
  case on the `eval_scores` path (dedupe key `run_id || at`), replacing atomic
  array comparison for that path.

Verification flagged the sharpest editorial hazard here: oc-checkpoint-protocol's own
doctrine sentence — *"A wire bump is never a breaking change here"* — must be revised
**in the same PR** that ships rotation, or the doc contradicts the release it rides
in. Old files still validate (1.0/1.1/1.2 all accepted); what breaks is the read
contract for completeness. That is precisely the major-version story: nothing
migrates destructively, but a documented contract moves.

Also required by verification: 1.2-stamped `eval_scores` writes MUST include
`run_id` or `at` (both optional today) so the dedupe key is defined; legacy entries
fall back to whole-entry structural equality. And `references/semver-decisions.md`
item 1 must widen from "field rename/removal" to "any wire `protocol_version` bump,
including merge/append-semantics changes" — under the current literal reading, 1.2
would slip to Minor.

> **What's wired vs. what's a pattern** (house convention): `reflect` leans on real
> tooling — it reads `.checkpoints/history/*.eval.ndjson`, `.checkpoints/scorecard.json`
> (P1 output), and `.opchain/hindsight/lessons.jsonl` (P2 output). `adopt`'s gate
> shells out to the oc-prompt-ops eval runner. The lifecycle verbs are agent behaviors
> with state persisted to the tracked checkpoint and to one-file-per-rule diffs in
> `.opchain/rules/` — every transition is a git-diffable, PR-reviewable edit.

## The rule ledger — `.opchain/rules/<id>.md`

One Markdown file per rule (a deliberate merge-hygiene choice: parallel PRs adding
different rules touch different files and never conflict). Frontmatter carries:
`id`, `status` (the lifecycle enum), `precedence: learned-rule` (always lowest),
`scope` / `target_skill`, `evidence[]` (source path + anchor + verbatim excerpt),
`recurrence`, `proposed_at` / `approved_at` / `adopted_at` / `expires_at` /
`last_revalidated_at`, `baseline_ref` (the frozen `prompts/opchain-eval` baseline it
was proven against), `eval_delta`. Body = the human-readable rule text.
`prompts/opchain-eval/rules-manifest.json` maps rule ids → goldset case ids.

## Boundaries — what oc-evolve does NOT own

| Concern | Owner |
|---|---|
| Routing, "what should I do next?", cross-project status | `oc-orchestrator` — evolve looks **backward** and governs rules; it never routes. (`evalTrendDeclining()` in `pickNext` lands in `scripts/checkpoint.mjs`, same template as `budgetExceeded()`, owned by neither skill.) |
| Eval runner, goldsets, judge config, baseline/regress mechanics | `oc-prompt-ops` — `/oc-evolve adopt` is a **consumer** of `/oc-prompt regress`; evolve never reimplements an eval loop. |
| Usage metering + anonymized `/dashboard` aggregates | `oc-telemetry-ops` — telemetry records *that* skills ran; evolve interprets *how well*. Neither reads the other's store. |
| Retrieval discipline for the hindsight index | `oc-rag-forge` — the hindsight kit dogfoods rag-forge; evolve reads retrieved lessons, never owns the index. |
| Semver, changelog, lockstep bump, shipping the graduated change | `oc-release-ops` — graduate produces a *packet*; release-ops decides when/how it ships. |
| Branch / commit / PR mechanics | `oc-git-ops` (with its bug-check / docs-forge / repo-ops gates intact — graduation PRs skip no gates). |
| Computing trends; emitting/decaying directives; SessionStart re-injection; the CLAUDE.md blocks | **P1 scorecard kit** — evolve reads `scorecard.json` as input; it never recomputes slopes or writes directives. |
| Capturing lessons; BM25 index; top-k per-prompt injection | **P2 hindsight kit** — evolve clusters *over* lessons; injection stays the kit's job. |
| The checkpoint wire format | `oc-checkpoint-protocol` — evolve is a reader of the contract, not its author. |

The load-bearing asymmetry: the two kits are **mechanical data plumbing with zero
judgment by design** (safety invariant: learned content is data). oc-evolve is the
only place judgment happens — and every judgment terminates at a human gate.

## Why a new skill (not an extension) — one line per neighbor

- **vs `oc-orchestrator`.** The orchestrator is a *read-only, forward-looking*
  coordinator ("NEVER writes", "no build artifacts"). oc-evolve is *backward-looking
  governance* that writes `.opchain/rules/` diffs and runs approval gates. Folding a
  write-heavy gated lifecycle into the read-only router breaks the constraint that
  makes `/oc-ops` trustworthy.
- **vs `oc-prompt-ops`.** prompt-ops's unit is *a prompt*; evolve's unit is *a
  cross-skill behavioral rule* with a human-gated lifecycle. prompt-ops is the
  **engine of the prove gate**, not its governor.
- **vs `oc-telemetry-ops`.** telemetry's trust posture is *default-OFF,
  records-never-judges*. Adding outcome interpretation there would poison the privacy
  stance that makes opt-in defensible.
- **vs `oc-rag-forge`.** rag-forge builds retrieval systems as a product skill; the
  hindsight kit is a repo-local *instance* of its discipline. A rule-lifecycle
  governor inside rag-forge would be a blurry second mode — what the 1.7 boundary
  test rejects.
- **vs `oc-release-ops`.** release-ops ships versions on a cadence; graduation is a
  per-rule promotion whose evidence and lifecycle live outside any release window.
- **vs the P1/P2 kits.** The kits are deliberately mechanical with zero judgment.
  The judgment layer with human gates has to be a **skill**, so the lifecycle
  versions with the catalog, mirrors publicly, and is governed by
  `skills/CHANGELOG.md` like every other cross-skill contract.

Keeping it separate gives the 2.0 invariants **one enforcement point**: recurrence
≥ 3, fixed precedence, and expiry are contracts — spread across five skills they
drift; owned by one governor they're testable in CI.

## Checkpoint shape

```jsonc
"progress_table": [
  { "id": "reflect",       "label": "Sweep outcome signals",          "status": "not_started" },
  { "id": "cluster",       "label": "Cluster patterns (rec >= 3)",    "status": "not_started" },
  { "id": "propose",       "label": "Draft rule diffs (×N)",          "status": "not_started" },
  { "id": "review-gate",   "label": "★ Human review",                 "status": "not_started" },
  { "id": "validate",      "label": "Prove: baseline-and-regress",    "status": "not_started" },
  { "id": "adopt-gate",    "label": "★ Adoption approval",            "status": "not_started" },
  { "id": "adopt",         "label": "Adopt (re-injection enabled)",   "status": "not_started" },
  { "id": "graduate",      "label": "Upstream packet (optional)",     "status": "not_started" }
]
```

`skill_state` holds the sweep provenance (`signals_swept` counts), the cluster set,
and a rule ledger that **mirrors** `.opchain/rules/<id>.md` frontmatter — the rule
file is source of truth; the ledger is the index. Pending proposals are filed as
`blockers[]` with `needs: "user_decision"` — but surfaced at a **dedicated advisory
sub-rank below genuine execution blockers** (see oc-orchestrator changes; a proposed
rule must never outrank a real pipeline blocker in `/oc-ops next`).

# The repo-local kits (Layer 2) — shipped artifacts, not skills

Both kits are consumer-repo deliverables (scripts + hooks + config), documented by
the skills that own their disciplines, installable in any repo with zero opchain
release. In the opchain repo they're committed directly; for consumer repos they
ship as an opt-in kit. **Absent kit = exact v1.8 behavior** (no failure mode, only
an absence of improvement).

## P1 — Outcome Scorecard kit

| Artifact | Purpose |
|---|---|
| `scripts/scorecard.mjs` | `harvest` (sample eval_scores[] + FAIL reports → ndjson), trend computation (slope/moving-avg/volatility/streak per skill × dimension), directive emit/expire (recurrence ≥ 3, decay on recovery), `render` (CLAUDE.md block + HTML view), `rotate` (spill to history, stay under 32KB), `inject` (SessionStart stdout) |
| `.claude/hooks/outcome-scorecard.sh` | Stop mode → harvest at session end; SessionStart mode → inject active directives |
| `.checkpoints/history/<skill>.eval.ndjson` | Git-tracked append-only archive of record (`.gitattributes merge=union`) |
| `.checkpoints/scorecard.json` | Git-tracked computed rollups + active/expired directives (derived-but-tracked; regenerate post-merge with `harvest`) |
| CLAUDE.md `opchain:scorecard` block | Bounded, delimited, regenerated — the SDK/ephemeral fallback channel |
| `scripts/checkpoint.mjs` delta | `evalTrendDeclining()` + `pickNext()` tiebreaker (the `budgetExceeded()` template) — pays off oc-orchestrator's currently-aspirational "a skill trending down is a candidate for the next pass" |
| `scripts/merge-checkpoint.mjs` delta | Union-merge case on the `eval_scores` path (dedupe `run_id \|\| at`; structural-equality fallback for legacy entries) |

Harvest constraints from verification: report-file scan (monotonic
`eval-round-M.md`) is the primary source; eval_scores snapshot sampling is
best-effort; **oc-bug-check harvest is verdict + per-check statuses + counts +
timestamp ONLY — never report bodies** (FAIL reports can embed detected secret
fragments; mirroring bodies into a tracked ndjson would re-commit the secret the
gate blocked).

## P2 — Hindsight kit

| Artifact | Purpose |
|---|---|
| `scripts/hindsight.mjs` | `ingest` (5 harvesters: eval FAILs, `audits/*.md` findings, postmortem lessons blocks, PR reviews, checkpoints; structural chunking; recurrence dedup; sanitizer + quarantine), `query` (pure-JS BM25, faceted by skill, ranked relevance × recurrence × freshness), `rebuild` (deterministic, off the hot path), `validate`, `promote`/`expire`, `eval` (recall@k / MRR regression gate vs frozen baseline) |
| `.opchain/hindsight/lessons.jsonl` | Git-tracked lesson memory (source of truth) + `manifest.json` (sha-gated incremental reingest) + `goldset.jsonl` |
| `.opchain/hindsight/index.json` | Gitignored BM25 index, rebuilt from the JSONL on any fresh clone/worker |
| `.claude/hooks/hindsight-retrieve.sh` | UserPromptSubmit + SessionStart: derive skill hint, inject top-k as a fenced advisory block; fast-exit when no store/hint |
| `scripts/merge-hindsight.mjs` | Union-by-id merge driver (max counters, newest timestamps, most-restrictive status), registered via `install-git-drivers.mjs` |

Primary injection defense (per verification): **human PR review of every appended
lesson** — the regex sanitizer is defense-in-depth, not the load-bearing control. A
lesson only becomes retrieval-eligible (`staged → active`, recurrence ≥ 2) after
landing in a reviewed diff.

# Sprint plan (oc-app-architect Phase 4 format)

Build order follows the dependency chain: substrate → measurement → memory →
governor → shipping. Each sprint is independently demoable; sprints 1–3 are
zero-release (repo-local); the release cost concentrates in sprints 4–5.

## Sprint 1: Wire 1.2 substrate — "the accumulator exists"
**Deliverables:** oc-checkpoint-protocol SKILL.md Wire-1.2 section (+ doctrine-sentence
revision); `checkpoint.mjs` validator for 1.2 (+ optional eval_scores fields, ACCEPTED
versions, rotation warn); `merge-checkpoint.mjs` union-merge on the eval_scores path;
`.gitattributes` ndjson union rule; 1.1→1.2 stamp sweep (oc-migration-ops job).
**Tests:** validator accepts 1.0/1.1/1.2; union-merge coalesces parallel appends;
rotation spills at threshold; legacy-entry dedupe fallback.
**Definition of done:** two branches appending different eval rows merge conflict-free;
`checkpoint:validate` green on all three wire versions.
**Effort:** ~1–2 days.

## Sprint 2: P1 Outcome Scorecard kit — "the trend is visible"
**Deliverables:** `scorecard.mjs` (harvest/report/render/rotate/inject/expire);
`outcome-scorecard.sh` + settings.json Stop/SessionStart entries; CLAUDE.md managed
block; `evalTrendDeclining()` + `pickNext` tiebreaker; oc-orchestrator +
oc-telemetry-ops SKILL.md changes.
**Tests:** N≥3 recurrence gate; directive expiry on slope recovery; idempotent
re-harvest; secret-free bug-check harvest (verdict/counts only).
**Definition of done:** a 3-run declining dimension emits a directive that appears in
`/oc-ops next` and expires when scores recover.
**Effort:** ~2–3 days.

## Sprint 3: P2 Hindsight kit + emitter contracts — "the memory retrieves"
**Deliverables:** `hindsight.mjs` (ingest/query/rebuild/validate/promote/expire/eval);
`hindsight-retrieve.sh` + settings entries; `merge-hindsight.mjs` + driver
registration; emitter contracts (oc-code-auditor `audits/`, oc-monitoring-ops
`:lessons:` markers, oc-app-architect report contract, oc-bug-check harvest surface);
oc-rag-forge hindsight mode docs.
**Tests:** deterministic chunking; sanitizer/quarantine + no-leak assertion;
union-by-id merge; retrieval goldset recall@k baseline.
**Definition of done:** a committed FAIL report becomes a lesson that surfaces top-k
for the matching skill on the next relevant prompt.
**Effort:** ~2–3 days.

## Sprint 4: oc-evolve — "the governor governs"
**Deliverables:** `skills/oc-evolve/SKILL.md` + references bundle; `evolve.mjs`
(reflect/propose/review/adopt/retire/revalidate/render/validate/status/graduate);
`.opchain/rules/` store + README spec + rules validator (CI); rules-manifest +
`--cases/--rule` regress flags (oc-prompt-ops changes); cost gates
(oc-cost-ops changes); flags registry entries.
**Tests:** lifecycle state machine (no transition without its gate); precedence
validator rejects non-`learned-rule`; prove-before-adopt blocks on regress FAIL;
advisory sub-rank never outranks execution blockers.
**Definition of done:** a reflect pass over sprints 2–3's accumulated history
proposes a rule; adopt is blocked until the goldset gate passes AND a human approves.
**Effort:** ~2–3 days.

## Sprint 5: Graduation + release mechanics — "2.0 ships"
**Deliverables:** oc-git-ops graduation flow (`evolve/` branches, PR variant,
`--graduate`); oc-release-ops intake + semver-decisions widening + verify gate row;
oc-docs-forge `### Self-improvement state`; oc-repo-ops learning-surface gates +
clean guardrail; orchestrator.md re-sync (all 30 bundles); lockstep bump 29→30 →
2.0.0; skills/CHANGELOG.md 2.0.0 entry (BREAKING callout); release-pinned surfaces
(`Header.astro CURRENT_RELEASE`, `tests/site-release-chip.test.js`,
`tests/release-surfaces.test.js`, `changelog-and-scenarios.spec.ts`,
changelog.astro/styleguide.astro copy, `server.json`, skills/README.md table,
gen-flags/gen-catalog, regenerated zip); staging → prod manual deploy.
**Definition of done:** `/api/health` serves the 2.0 SHA; a proven rule graduates via
an `evolve/` PR riding every gate; the mirror picks up the 30-skill snapshot.
**Effort:** ~3–4 days (release mechanics comparable to v1.8.0 per the
release-pinned-surfaces record).

**Total: roughly 10–15 focused days.** Sprints 1–3 are useful in any consumer repo
with zero release; a consumer repo adopting only the kits gets P1+P2 self-improvement
on v1.8.1 skills today.

# Appendix A — Verification corrections (what changed between proposal and plan)

Fifteen independent reviewers fact-checked the proposed per-skill changes against the
live SKILL.mds. Material corrections folded into this plan:

1. **checkpoint-protocol:** the "a wire bump is never a breaking change" doctrine
   sentence must be revised in the same PR as rotation; `run_id||at` dedupe requires
   run_id-or-at on 1.2 writes (structural-equality fallback for legacy);
   trend/advisory semantics kept OUT of the protocol skill (format + location only).
2. **orchestrator:** proposed rules must NOT ride the rank-1 `needs: user_decision`
   blocker path — dedicated advisory sub-rank below execution blockers; document the
   full tiebreaker chain (pipeline order is no longer "THE" tiebreaker); fix stale
   `memory_user_edits` text in the same pass.
3. **git-ops → docs-forge reroute:** the "learned rules changed" packet section is
   docs-packet *content*, which git-ops explicitly does not own.
4. **bug-check:** harvest verdict/statuses/counts/timestamp ONLY — report bodies can
   embed detected secret fragments (`sk_live_...`) and mirroring them into a tracked
   ndjson would re-commit the secret the gate blocked.
5. **app-architect:** recurrence notes are a post-verdict annotation (Evaluator
   grades with isolated context first); advisory context is Generator-only.
6. **signal-forge:** the "skill-health signals as a catalog class" piece contradicted
   the skill's own boundaries — dropped.
7. **cost-ops:** deferral enforcement lives in oc-evolve (cost-ops emits verdicts,
   never enforces); adoption-run costing reuses the prompt-ops path (no double count).
8. **repo-ops:** all learning-surface gates conditional on kit presence (absence is a
   pass, not a warning); `clean` never touches rules.
9. **monitoring-ops:** lessons markers use a distinct `:lessons:` token — the
   existing `:postmortem:` marker has PM-MCP ticket-transition semantics.
10. **release-ops:** `semver-decisions.md` item 1 widened, or 1.2 slips to Minor
    under a literal reading; no-write-through enforced as a `/oc-release verify` gate
    row, not loose prose.
11. **rag-forge:** hindsight documented as a named exception to Principle 9 (no
    vector-DB pack) and as single-shot utilities outside the tri-agent loop.
12. **prompt-ops:** scoped regress is adoption evidence only — the CI merge gate
    remains the full suite (anti-gaming rule stated in Principle 3).
13. **docs-forge:** `### Self-improvement state` is conditional-REQUIRED (optional
    would contradict "Silence is not a pass"); the four-field fragment stays stable.
14. **code-auditor:** the PM-comment template naming the checkpoint as "Full report"
    is an internal contradiction the same PR must fix.

# Appendix B — Design provenance

The architecture synthesizes three independently designed and adversarially reviewed
(all SOUND) candidate approaches: **P1 "Outcome Scorecard"** (measured/automatic —
numeric trends, decaying directives), **P2 "Hindsight"** (retrieval/automatic — a
freshness-decaying RAG memory over committed outcomes, dogfooding oc-rag-forge), and
**P3 "oc-evolve"** (governed/human-in-the-loop — cross-skill reflection, approval
gates, prove-before-adopt, upstream graduation). 2.0 ships all three as layers:
P1/P2 as mechanical repo-local kits (zero judgment by design), P3 as the one skill
where judgment happens. Full designs, feature lists, and review verdicts live in the
2026-07-12 planning session; the comparison artifact is published at
claude.ai/code/artifact/eac3aaea-697a-4de9-a6f2-ba970178e1ed.
