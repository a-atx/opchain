# opchain Trademark Policy

"opchain" and the opchain logo identify this project and the quality of the work we publish. The code is Apache-2.0; the Apache License §6 expressly does **not** grant trademark rights, so this document says what we're comfortable with. It follows the pattern of the Linux Foundation, Rust Foundation, and PSF policies.

## You can, without asking

- Use "opchain" to truthfully refer to this project, its skills, plugin, or MCP server (nominative use), including in articles, talks, tutorials, and package metadata.
- Say your project or product is *"built with opchain"*, *"compatible with opchain"*, or *"for opchain"* — as long as the phrasing doesn't imply we built, endorse, or maintain it.
- Redistribute **unmodified** releases (zips, the plugin, the repo) under the opchain name — that's what the license is for.
- Use the name in a fork's description ("fork of opchain") while the fork clearly carries its own name.

## Please ask first (opchain.dev → hello, or open an issue)

- Using "opchain" or a confusingly similar name **in the name of** your product, service, company, domain, or package (e.g. "opchain-pro", "OpChain Cloud").
- Using the opchain logo in a modified form, or any use implying sponsorship, endorsement, or affiliation.
- Selling merchandise bearing the name or logo.

## Notes

- Modified redistributions must not be presented as official opchain releases; per Apache-2.0 §4(b), state prominently that you changed the files.
